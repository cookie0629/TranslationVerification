# HW5 — темпоральные спецификации и проверка модели

Основной инструмент: **nuXmv 2.0.0**, совместимый с NuSMV 2.6.0. Модель взята из части Б [P09](../TVDSL/practices/P09_temporal_specs.md): протокол «запрос — ответ». Каталог содержит исходную модель с возможным бесконечным ожиданием, исправленную модель без такого ожидания, пять LTL/CTL-спецификаций, сценарий проверки и сохранённые исходные логи.

## Модель и допущения

Единственная переменная `state` принимает четыре значения: `idle`, `req`, `ack`, `error`. Начальное состояние — `idle`. Переходы исходной модели: `idle → req`, `req → req` **или** `req → ack`, `ack → idle`, `error → error`. Переход `req → req` может выбираться бесконечно; ограничений справедливости нет. `error` входит в область переменной, но из начального состояния недостижим. Каждый переход — один дискретный атомарный шаг. Модель конечна и не описывает время, параллелизм, таймауты и содержимое сообщений.

В [исправленной модели](models/request_response_fixed.smv) удалён только переход `req → req`. Оба файла содержат одинаковые свойства; различается лишь множество следующих состояний для `req`.

## Запуск

Нужен `nuXmv` или `NuSMV` в `PATH`. В Windows можно скачать официальный архив nuXmv 2.0.0 `https://es-static.fbk.eu/tools/nuxmv/downloads/nuXmv-2.0.0-win64.tar.gz`. SHA-256 архива: `DF7A489A7A257BC187D9AECC01368DB6A5B6E57BD0C061FCA385E3E046A8D31E`. Исполняемый файл находится в `bin/nuXmv.exe`. Python 3.10+ нужен только для сценария сводки.

Из каталога `HW5_TemporalMC` в PowerShell:

```powershell
python run_checks.py --exe C:\path\to\nuXmv.exe
```

Если инструмент ещё не установлен, можно воспроизвести использованный здесь запуск без системной установки:

```powershell
New-Item -ItemType Directory -Force .tools | Out-Null
Invoke-WebRequest 'https://es-static.fbk.eu/tools/nuxmv/downloads/nuXmv-2.0.0-win64.tar.gz' -OutFile .tools\nuXmv-2.0.0-win64.tar.gz
Get-FileHash .tools\nuXmv-2.0.0-win64.tar.gz -Algorithm SHA256
tar -xzf .tools\nuXmv-2.0.0-win64.tar.gz -C .tools
python run_checks.py --exe .\.tools\nuXmv-2.0.0-win64\bin\nuXmv.exe
```

Сверьте напечатанный хеш с указанным выше. `.tools` исключён из сдачи через `.gitignore`.

Если `nuXmv` или `NuSMV` уже в `PATH`, достаточно `python run_checks.py`. Сценарий запускает оба файла с флагом `-s`, проверяет наличие всех пяти результатов, выводит краткую таблицу и сохраняет полный вывод в [logs](logs). `-s` отключает пользовательский файл инициализации; используются стандартные процедуры проверки nuXmv (BDD, без SAT/BMC и без условий справедливости). Сохранённые логи получены командой `python run_checks.py` с nuXmv 2.0.0 на Windows.

Можно запустить инструмент непосредственно:

```powershell
nuXmv -s models\request_response_bug.smv
nuXmv -s models\request_response_fixed.smv
```

NuXmv может завершиться с кодом 0 и при ложной спецификации. Ориентируйтесь на строки `-- specification ... is true/false` и контрпример. Сценарий проверяет ожидаемые значения отдельно.

## Свойства и результаты

`at_req`, `at_ack`, `at_idle`, `at_error` — булевы обозначения соответствующих значений `state`. `G`, `F`, `X` — операторы LTL; `EF` — оператор CTL. Все свойства проверяются в начальном состоянии и на всех допустимых путях, кроме экзистенциального `EF`.

| ID | Тип | Требование | Формула | Исходная | Исправленная |
| --- | --- | --- | --- | --- | --- |
| S1 | безопасность | Ошибка никогда не достигается | `G !at_error` | true | true |
| S2 | безопасность | После подтверждения следует ожидание | `G (at_ack -> X at_idle)` | true | true |
| S3 | безопасность | После запроса остаётся запрос или приходит подтверждение | `G (at_req -> X (at_req \| at_ack))` | true | true |
| L1 | живость/ответ | Каждый запрос когда-нибудь подтверждается | `G (at_req -> F at_ack)` | **false** | true |
| C1 | достижимость, CTL | Существует путь к подтверждению | `EF at_ack` | true | true |

Подробный разбор трассы и обоснование каждого результата находятся в [REPORT.md](REPORT.md). Файлы [bug.nuxmv.txt](logs/bug.nuxmv.txt) и [fixed.nuxmv.txt](logs/fixed.nuxmv.txt) — неизменённый вывод инструмента.
