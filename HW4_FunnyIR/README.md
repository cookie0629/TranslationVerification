# HW4 — промежуточное представление, CFG и оптимизации Funny

Этот этап принимает **аннотированное AST из HW3** и создаёт трёхадресное IR для функций Funny. Из исходного текста цепочка запускается автоматически: HW2 → HW3 → HW4. При ошибках HW3 генерация IR прекращается с сообщением и ненулевым кодом выхода.

## Быстрый запуск

Требуются Python 3.10+, GCC для сборки парсера HW2. В PowerShell из корня репозитория:

```powershell
cd HW2_FunnyParser_C
gcc -std=c99 -O2 -Wall -Wextra -pedantic parser.c -o funny_parser.exe
cd ..\HW4_FunnyIR
python hw4.py examples\arithmetic.funny
python hw4.py examples\control.funny --dot-dir examples\graphs
python hw4.py --json examples\arrays_calls.funny
python tests\run_tests.py
```

В Linux/macOS выходной файл компиляции называется `funny_parser`, пути используют `/`. Тестовый сценарий сам компилирует HW2 во временный каталог и не оставляет исполняемых файлов в проекте.

Проверку можно запустить непосредственно на результате HW3:

```powershell
python ..\HW3_FunnyTypes\checker.py --json examples\arithmetic.funny > annotated.json
python hw4.py --ast annotated.json
```

`--ast` принимает JSON-объект HW3 `{ast, diagnostics}` или сам аннотированный узел `Module`. Если `diagnostics` не пуст, IR не строится. Флаги `--checker` и `--parser` позволяют указать другие пути к предыдущим этапам. Без имени файла исходный текст читается из stdin.

## Флаги оптимизации и форматы вывода

По умолчанию включены распространение/вычисление констант, алгебраические упрощения и удаление мёртвого кода. Каждый проход можно отключить отдельно:

| Флаг | Действие |
| --- | --- |
| `--no-const` | отключить локальное распространение и вычисление констант |
| `--no-algebra` | отключить `x+0`, `x*1`, `x/1` и подобные преобразования |
| `--no-dce` | отключить удаление мёртвых вычислений |
| `--no-opt` | отключить все три прохода |
| `--json` | вывести JSON с отступами и переносами строк вместо текстового представления; формат остаётся пригодным для программного чтения |
| `--dot-dir DIR` | сохранить графы CFG и конфликтов в DOT |

Текстовый вывод содержит IR **до и после** оптимизации, рёбра CFG, граф конфликтов временных значений, назначенные цвета регистров и метрики. `--json` выводит ту же структуру с вложенными отступами: функции, версии `before`/`after`, блоки и инструкции видны отдельно. Для короткого просмотра в терминале используйте запуск без `--json`. Готовые примеры: [арифметика и оптимизация](examples/arithmetic.ir.txt), [ветвление и цикл](examples/control.ir.txt), [CFG в DOT](examples/graphs/sum_to.cfg.dot), [граф конфликтов в DOT](examples/graphs/sum_to.interference.dot).

### Демонстрация флага `--no-algebra`

Файл [algebra.funny](examples/algebra.funny) содержит все три выражения `x + 0`, `a * 1` и `b / 1`. Из каталога `HW4_FunnyIR` выполните:

```powershell
python hw4.py examples\algebra.funny
python hw4.py --no-algebra examples\algebra.funny
```

В секции `After optimization` результат различается так:

| Правило | Обычный запуск | С `--no-algebra` |
| --- | --- | --- |
| `x + 0` | `%t1 = x` | `%t1 = x + 0` |
| `a * 1` | `%t3 = a` | `%t3 = a * 1` |
| `b / 1` | `%t5 = b` | `%t5 = b / 1` |

Полные снимки вывода: [с алгебраическими упрощениями](examples/algebra.enabled.ir.txt) и [без них](examples/algebra.disabled.ir.txt). В обоих запусках распространение констант и DCE остаются включёнными. Поэтому константы `0` и `1` уже подставлены в операнды, а число инструкций одинаково (`10 → 7`): флаг меняет сами операции на `copy`, а не обязательно сокращает количество инструкций.

## Формат IR и API для кодогенерации

Машинный JSON имеет верхние поля `version: 1`, `formulas`, `functions`, `optimizations`. Для каждой функции хранятся `before`, `after` и `metrics`. Каждая версия функции содержит `name`, `params`, `returns`, `locals`, `contracts`, `entry`, `temp_types`, `blocks`, `liveness`, `interference`, `metrics`.

Операнд — либо ссылка `{"ref":"%t1"}` / `{"ref":"r"}`, либо константа `{"const":5,"type":"int"}`. Имена `%tN` обозначают временные значения; обычные имена обозначают переменные Funny. Инструкции в `block.instructions`:

| `op` | Операция |
| --- | --- |
| `const`, `copy` | константа, присваивание |
| `unary`, `binary` | унарная и бинарная операция |
| `array_get`, `array_set` | чтение массива и функциональное обновление с копированием |
| `call` | вызов с упорядоченными `args` и списком `dests` для нескольких результатов |
| `assert`, `assume` | проверяемое условие или ограничение пути |
| `spec_assert`, `spec_assume` | предикат с формулой/квантором, сохранённый как AST для верификатора |

У каждого блока ровно один `terminator`: `jump`, `branch` или `ret`. Поля `successors` и `predecessors` задают CFG; `entry` называет начальный блок. В `liveness` записаны множества `in`/`out`. `interference.edges` — списки соседей для временных значений, `interference.colors` — жадная раскраска с номерами `R0`, `R1`, ... . Ограничение на число регистров и вставка spill-инструкций пока не реализованы. Позиции `line`/`column` инструкций происходят из AST и пригодны для сообщений следующего этапа.

`requires` и `ensures` остаются в `contracts`, инвариант — в заголовке блока цикла, определения формул — в `formulas`. Их нельзя незаметно удалить при оптимизации. Встроенный интерпретатор проверяет исполняемые `assert`/`assume`, но спецификации с кванторами и ссылками на формулы хранит для дальнейшей верификации без исполнения.

## Корректность и тесты

Команда `python tests/run_tests.py` прогоняет настоящую цепочку HW2→HW3→HW4. Для одинаковых входов она сравнивает результаты интерпретации IR до и после оптимизации: арифметика, ветвление, цикл, вызовы, несколько результатов, массивы и короткое вычисление `and`/`or`/`->`. Проверяются также структура CFG, корректность раскраски, независимое отключение проходов, сохранение формул/контрактов, DOT-экспорт и отказ при ошибке типов. Отдельные тесты подтверждают, что DCE сохраняет деление на ноль и чтение неинициализированной локальной переменной.

Интерпретатор использует 32-битные целые с переполнением по модулю 2³², проверяет деление на ноль и границы массивов. Это средство проверки оптимизаций, а не JVM-генератор. Подробные результаты и ограничения описаны в [REPORT.md](REPORT.md).
