# HW3 类型规则与限制简报

## 符号表

第一遍登记所有模块级函数和公式的参数/返回签名，检查全局重名。第二遍检查每个声明：函数有一层共同的参数、返回、`uses` 作用域；语句块和量词各压入新作用域。查找从内向外进行，声明时只检查当前作用域是否已有同名符号。量词另禁止与当前可见名称重名。函数可引用后面的函数，也能递归调用。

## 类型与统一

值类型为 `int`、`int[]`、`bool`；函数签名保存参数序列和返回序列。统一采用精确类型相等，不作转换。未知变量或已出错表达式使用内部错误哨兵，避免同一根错误产生大量连锁诊断。二元运算逐个检查两侧；调用逐个检查实参与形参，单值上下文要求恰好一个返回值。数组更新的 `Set(array,index,value)` 依次要求 `int[]`、`int`、`int` 并产生 `int[]`。

`uses x` 的类型起初是内部未知状态。首次右侧为确定的 `int` 或 `int[]` 且赋值有效时，将其类型写回符号表与 `VarDef` AST。之后赋值必须与该类型一致。这个推断只沿语句的 AST 遍历顺序进行；它不是控制流敏感的定点分析。读一个仍未知类型的局部变量会报错。

## 诊断与下游接口

诊断对象固定为 `{line,column,message}`，位置来自 HW2 的 token/AST。JSON 顶层固定为 `{ast,diagnostics}`。HW4 可先检查 `diagnostics` 是否为空，再使用表达式 `type`、调用签名和已降低的 `Set` 节点生成 IR。HW2 若提供部分 AST 并报告语法错误，语义阶段停止，以免把缺失节点误当作合法输入。

## 已知限制

- Funny 无用户可声明的 `bool` 或 `string`，本实现不引入它们；公式返回 `bool` 仅作为内部类型。
- 无重载、隐式转换、控制流敏感的确定赋值检查、数组越界检查、函数返回值路径检查。
- 局部声明只来自函数头部的 `uses`；Funny 语法没有块内声明语句。嵌套块仍有独立符号表，便于后续扩展。
- 复用 HW1 的 ASCII 词法器；非 ASCII 源文本（包括注释内容）由 HW2 报词法错误。
