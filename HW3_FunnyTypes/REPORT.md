# HW3 — отчёт о типах и ограничениях

## Таблицы символов и области видимости

Анализатор работает в два прохода. Сначала он собирает в глобальную таблицу сигнатуры всех функций и формул и сообщает о повторных именах. Поэтому функция может вызывать саму себя или функцию, определённую позже. Затем каждое объявление проверяется отдельно. Параметры, возвращаемые значения и локальные переменные `uses` находятся в общей области функции; блоки и кванторы добавляют вложенные области. Поиск имени идёт из внутренней области наружу. При объявлении проверяется повтор только в текущей области. Для переменной квантора дополнительно запрещено совпадение с видимым именем.

## Типы и правила проверки

Поддерживаемые типы значений: `int`, `int[]` и внутренний `bool`. Пользовательские переменные допускают только `int` и `int[]`; `bool` нужен для условий и формул. Сигнатура функции хранит упорядоченные списки типов параметров и результатов. Унификация здесь означает точное совпадение типов; неявных преобразований нет. Проверяются оба операнда выражения, аргументы вызова, число результатов и типы целей присваивания.

Для `Set(array, index, value)`, созданного парсером из `a[i] = v`, требуются соответственно `int[]`, `int`, `int`, а результат имеет тип `int[]`. Параметры и переменные кванторов нельзя изменять. Если имя или тип уже ошибочны, внутренний маркер ошибки предотвращает каскад одинаковых сообщений.

## Вывод типов локальных переменных

Объявление `uses x` сначала имеет неизвестный тип. Первое корректное присваивание значения типа `int` или `int[]` фиксирует тип в таблице символов и в узле `VarDef` аннотированного AST. Дальнейшие присваивания должны совпадать с ним. Чтение до вывода типа и отсутствие подходящего присваивания вызывают диагностику. Вывод выполняется в порядке обхода AST; это не анализ потока данных по всем ветвям управления.

## Диагностика и формат для следующего этапа

Каждая диагностика имеет вид `{line, column, message}` с координатами из токенов и AST HW2. Верхний уровень JSON — `{ast, diagnostics}`. Следующий этап может сначала проверить, что `diagnostics` пуст, а затем использовать `type` выражений, сигнатуры вызовов и узлы `Set` для построения IR. Если парсер сообщил об ошибке и выдал частичное дерево, семантическая проверка на нём не выполняется.

## Ограничения

- Нет пользовательских переменных типа `bool`, строк, перегрузки и неявных преобразований.
- Нет анализа определённой инициализации на всех путях, проверки границ массивов, истинности контрактов и наличия присваивания возвращаемому значению на каждом пути.
- Локальные объявления задаются только списком `uses` в заголовке функции; синтаксис Funny не содержит операторов объявления внутри блока. Для вложенных блоков всё же создаются отдельные области для последующего расширения.
- Используется ASCII-лексер HW1. Не-ASCII байты, в том числе в комментариях, HW2 считает лексической ошибкой.
