# HW3 — Семантический анализ и проверка типов Funny

Программа [checker.py](checker.py) получает JSON AST от парсера HW2 через его режим `--json`. В обычном терминальном режиме HW2 показывает дерево с отступами; машинный формат для HW3 остаётся отдельным. Анализатор собирает сигнатуры функций и формул, проверяет имена и типы, затем возвращает аннотированное AST и список ошибок. Поддерживаются рекурсивные вызовы и обращения к функциям, объявленным ниже по тексту.

## Сборка и запуск

Требуются Python 3.10+ и компилятор C99 (например, GCC). В PowerShell из корня репозитория:

```powershell
cd HW2_FunnyParser_C
gcc -std=c99 -O2 -Wall -Wextra -pedantic parser.c -o funny_parser.exe
cd ..\HW3_FunnyTypes
python checker.py tests\valid.funny
python checker.py tests\errors.funny
python checker.py --tree tests\errors.funny
python checker.py --json tests\valid.funny
python tests\run_tests.py
```

В Linux/macOS соберите HW2 с `-o funny_parser` и используйте `/` в путях. Если исполняемый файл парсера находится в другом месте, передайте `--parser ПУТЬ`. Если не указать файл Funny, программа читает исходный текст из стандартного ввода.

## Вывод в терминал и сообщения об ошибках

По умолчанию успешная проверка показывает дерево AST с отступами и типом каждого выражения. При ошибках программа выводит **на stderr** сначала количество ошибок, затем список в порядке строк и столбцов. Каждая запись содержит категорию и конкретное объяснение. Например, для `tests/errors.funny` начало вывода такое:

```text
Type check: FAILED (9 error(s))
Diagnostics (source order):
  1. 1:13 [NameError] duplicate declaration 'a'
  2. 1:51 [NameError] duplicate declaration 'tmp'
  3. 1:61 [InferenceError] cannot infer type of local 'inferred': no valid assignment
  ...
```

При ошибках дерево скрыто ради краткости; `--tree` показывает его после диагностик. Таким образом, сообщение об ошибке видно сразу, а аннотированное AST можно показать отдельно на защите. Коды категорий: `NameError` — имя/объявление, `TypeError` — несовместимые типы, `ArityError` — число аргументов или результатов, `AssignmentError` — недопустимое присваивание, `InferenceError` — вывод локального типа, `SyntaxError`/`LexicalError` — ошибка из HW2.

Режим `--json` сохраняет машинный интерфейс: один JSON-объект UTF-8 с полями `ast` и `diagnostics` на stdout. Каждая диагностика имеет `line`, `column`, `category`, `message`; при ошибке краткое сообщение дополнительно печатается на stderr:

```json
{
  "ast": {"kind": "Module", "line": 1, "column": 1, "children": []},
  "diagnostics": [
    {"line": 2, "column": 3, "category": "TypeError", "message": "assignment to 'x': expected int, got bool"}
  ]
}
```

Схема дерева из HW2 сохраняет поля `kind`, `value` (при наличии), `line`, `column`, `children`. У выражений добавляется `type`: `int`, `int[]`, `bool` или `null` при ошибке. Функции, формулы и вызовы с несколькими результатами получают сигнатуру вида `func(T,...)->(T,...)`. Узлы `VarDef` содержат объявленный или выведенный тип; успешный вывод помечается `inferred: true`. Узел `Set` описывает функциональное обновление массива и имеет тип `int[]`. Это представление пригодно для построения IR в HW4.

Код завершения: `0` — ошибок нет; `1` — лексическая, синтаксическая или семантическая ошибка; `2` — ошибка запуска, чтения или взаимодействия с парсером. Все найденные независимые ошибки сообщаются за один запуск. При ошибках аннотированное дерево доступно через `--tree` или `--json`. Если HW2 уже сообщил о лексической или синтаксической ошибке, HW3 передаёт его диагностику и частичное AST без проверки типов на неполном дереве.

## Поддерживаемые конструкции и типы

- В Funny объявляемые типы — `int` и `int[]`. Внутренний `bool` используется для условий, предикатов и результатов формул; переменные типа `bool` не объявляются. Встроенная функция `length` имеет сигнатуру `int[] -> int`. Строки, перегрузка и неявные преобразования не поддерживаются.
- Проверяются арифметика, сравнения, логические операции, чтение и обновление массива, вызовы функций и формул, кванторы, присваивание нескольким переменным, `if`, `while`, `assert`, `assume`, `requires`, `ensures` и `invariant`. Операнды сравнения и арифметики имеют тип `int`; индекс и элемент массива также имеют тип `int`. Количество и тип аргументов и результатов вызова должны соответствовать сигнатуре.
- Параметры, возвращаемые значения и переменные `uses` принадлежат области функции. Блоки и кванторы создают вложенные области. Проверяются повторные объявления, неизвестные имена и чтение локальной переменной до вывода её типа. Параметры и переменные кванторов доступны только для чтения.
- Неаннотированная переменная `uses` получает тип `int` или `int[]` после первого корректного присваивания. Последующие несовместимые присваивания, чтение до вывода типа и невозможность вывести тип вызывают ошибки.

Это статическая проверка типов: программа не исполняется. Не проверяются переполнение, выход за границы массива, инициализация на всех путях управления, истинность контрактов и завершение циклов. Синтаксис `a[i][j]` разбирается в HW2, но тип `int[][]` отсутствует в заявленном подмножестве Funny, поэтому HW3 сообщает ошибку типа.

## Тесты

Команда `python tests/run_tests.py` запускает настоящий парсер HW2 и проверку типов. Девять оставленных программ покрывают корректные конструкции, вывод локальных типов, вызовы функций, объявленных ниже, кванторы, несколько независимых ошибок, неверные вызовы, ошибки массива и передачу синтаксической ошибки. Тесты также проверяют порядок сообщений, их категории, stderr, режим `--tree` и машинный `--json`. Ожидаемые позиции и фрагменты сообщений находятся в словаре `references` файла [tests/run_tests.py](tests/run_tests.py). После изменения HW2 его необходимо пересобрать перед запуском тестов HW3.

Правила типов и ограничения подробнее описаны в [REPORT.md](REPORT.md).
